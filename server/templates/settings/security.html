Data Encryption

Job commands, output, and escalation details are encrypted for this organization at rest. Mode: {{ company.encryption_mode | upper }}

{% if company.encryption_mode == 'managed' %}

Managed mode — your key is held by this Warden server (wrapped by the server's master key) so agents can keep reporting in 24/7 with no admin logged in.

Warning: BYOK means the platform never stores your passphrase. New agent data can't be encrypted while your vault is locked (e.g. after a server restart) until you unlock it again below. Forgetting the passphrase means that data is permanently unrecoverable.

Dual Approval

Destructive operations (remove agent, reboot, shutdown, delete user, and enable multi-session RDP) normally require two different admins to approve before they run — one admin can never unilaterally authorize them.

{% if company.require_dual_approval %}

Currently required. If your team only has one admin account, you'll never be able to produce a second approver — those operations will stay stuck pending approval forever unless you turn this off.

{% else %}

Currently off — a single admin can approve destructive operations alone. This is a real reduction in security; only turn dual approval back on if you trust it to reflect your actual risk tolerance.

{% endif %}

Automatic Agent Updates

When a new agent build finishes, endpoints normally stay on their current version until you click Update Agent yourself. Turning this on has the background scheduler do that automatically for any online endpoint that's behind the latest build.

{% if company.auto_update_agents %}

Currently on. Every online endpoint running an older agent version will get an Update Agent job automatically, within about a minute of a new build completing — no manual click needed. A bad build affects every endpoint that checks in before you catch it and push a fix.

{% else %}

Currently off — the default. You update each endpoint's agent yourself via the Update Agent button. Turn this on only once you trust that a bad build won't quietly roll out to your whole fleet before you notice.

{% endif %}

Agent TLS Trust Rotation

Stage one to three certificate SHA-256 fingerprints during a certificate change. Keep the current pin alongside the new pin until every endpoint has moved.

Safety: this requires dual approval. Test one endpoint before rotating the fleet.
